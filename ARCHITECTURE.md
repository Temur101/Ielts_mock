# IELTS PROCTOR SUITE: ARCHITECTURAL OVERVIEW

## 1. НАЗНАЧЕНИЕ СИСТЕМЫ

IELTS Proctor Suite (IELTSsync) — это веб-платформа для проведения экзаменов по международному стандарту Computer-Delivered IELTS (CD IELTS).

Платформа решает три ключевые задачи:
1. Аутентичная симуляция экзамена: интерфейс, идентичный официальному экзамену CD IELTS (split-screen для Reading, однократное воспроизведение аудио с блокировкой перемотки назад для Listening, редактор эссе с подсчётом слов для Writing, палитра навигации по 40 вопросам).
2. Автоматический конвейер создания тестов (AI Pipeline): загрузка 3 мастер-PDF файлов экзамена (Listening, Reading, Writing) с автоматическим парсингом текстов, многоколоночных таблиц, блок-схем, сеток заголовков и ключей ответов через мультимодальные модели Google Gemini без ручной верстки.
3. Централизованный прокторинг и оценивание: мониторинг кандидатов в реальном времени, автоматическая фиксация нарушений Anti-Cheat (переключение вкладок, выход из полноэкранного режима), синхронизация через Supabase Realtime и рабочее место преподавателя для проверки эссе.

## 2. ТЕХНОЛОГИЧЕСКИЙ СТЕК

- Frontend: React 18, Vite, Tailwind CSS, Lucide React (иконки).
- Backend / Database: Supabase (PostgreSQL, Realtime WebSocket Bus, Storage).
- Local Persistence: IndexedDB + LocalStorage (полная автономность и устойчивость к обрывам сети).
- AI Processing: Google Gemini API (модели Gemini 2.5 Flash / Standard Schema) для мультимодального извлечения структуры тестов из PDF.
- Repository Packaging: Repomix (упаковка кодовой базы для сквозного аудита).

## 4. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ УЗЛЫ

### А. Алгоритмическое ядро (src/lib/questionUtils.js)
Отвечает за приведение неструктурированных данных парсера к каноническому виду CD IELTS:
- determineQuestionCategory(q): определяет точный тип блока (MATCHING_HEADINGS, FLOW_CHART, TABLE_COMPLETION, FORM_COMPLETION, SUMMARY_COMPLETION, TFNG, YNNG, MULTIPLE_CHOICE).
- normalizeReferenceBox(raw): формирует чистый массив вариантов { key, label }, отделяя буквенные префиксы [A], (A), A. от текста.
- groupQuestionsIntoSets(questions, partOrPassageRefBox): группирует цепочки последовательных вопросов в единые блоки с единой инструкцией сверху и прикреплённым справочником вариантов.
- normalizeTemplateGaps(template, questions): конвертирует любые токены пропусков ([ ], ____, [blank]) в строгие системные маркеры {{N}}.
- splitSentenceAtGap(text): разделяет предложение на фрагменты до и после поля ввода для чистого инлайн-рендеринга.

### Б. Модуль чтения (PassageViewer.jsx + AnswerSheet.jsx)
Реализует разделенный экран 50/50:
- Слева расположен текст текущего пассажа с сохранением разбивки по абзацам (A, B, C...).
- Справа расположен непрерывный лист ответов, где сгруппированные блоки вопросов отображаются в зависимости от категории: кнопки True/False/Not Given, выпадающие списки List of Headings, инлайн-поля Summary Completion, таблицы сопоставления.

### В. Модуль аудирования (ListeningSection.jsx)
Обеспечивает прохождение 4 частей экзамена:
- Верхняя панель управляет воспроизведением 4 независимых аудиодорожек с правилом single-play (только один запуск без возможности перемотки назад).
- Центральная часть отображает форму, таблицу, блок-схему, схему карты с плашками меток [A]–[J] или вопросы с выбором вариантов.
- Нижняя панель предоставляет центрированную палитру быстрой навигации по 10 вопросам текущей части.

### Г. Отказоустойчивая шина данных (src/lib/supabase.js)
Исключает сбои экзаменационной сессии:
- При несоответствии локальной структуры данных удалённой схеме базы данных Supabase механизм resilientSupabaseOperation на лету вырезает проблемные поля, сохраняет валидную часть и логирует предупреждение, не прерывая экзамен студента.
- Все ответы и прогресс дублируются в локальный IndexedDB.
